# 实施计划: 居家老人情感分析及可视化系统（ElderMoodAI）

**分支**: `001-elder-mood-ai-system` | **日期**: 2026-05-06 | **规范**: specs/001-elder-mood-ai-system/spec.md

**输入**: 来自 `specs/001-elder-mood-ai-system/spec.md` 的功能规范

> ⚠️ **范围说明（2026-05-06 更新）**: 本阶段仅实现**纯前端效果**，所有数据使用 Mock 数据模拟，不涉及真实后端接口、数据库或 AI API 调用。

## 摘要

构建一套面向居家老人情感分析与可视化的**纯前端 Web 应用**，采用 Vue 3 + Element Plus + ECharts 5，使用 Mock.js 模拟所有数据。系统按照页面布局文档（左右分栏 + 顶部导航）实现 8 个核心页面，主题色为橙色与夕阳金，PC 端优先，兼容移动端基础访问。所有交互效果完整可演示，数据通过 Mock 数据模拟真实场景。

## 技术背景

**语言/版本**: JavaScript（Vue 3）
**主要依赖**:
- Vue 3 + Vue Router 4 + Pinia（状态管理）
- Element Plus（UI 组件库，后台管理布局）
- ECharts 5（折线图、饼图、柱状图、热力图、仪表盘）
- Mock.js（模拟数据生成）
- Vite（构建工具）

**存储**: 无后端，数据全部由 Mock.js 在前端内存中生成
**测试**: Vitest（前端单元测试，可选）
**目标平台**: PC 端 Web（Chrome/Edge/Firefox），兼容移动端基础访问
**项目类型**: 纯前端 SPA（单页应用）
**性能目标**: 页面切换 ≤300ms，图表渲染 ≤1秒（Mock 数据无网络延迟）
**约束条件**: 无后端依赖，所有数据在前端 Mock，可独立运行
**规模/范围**: 8 个核心页面，完整交互效果，Mock 数据覆盖所有展示场景

## Mock 数据设计

### 预置示例数据

| 数据类型 | 示例数量 | 说明 |
|---------|---------|------|
| 用户账号 | 3个 | 管理员/护理员/家属各1个，可切换角色演示 |
| 老人信息 | 10条 | 含不同授权状态、不同情感健康分 |
| 情感记录 | 90条 | 覆盖近30天，含各种情感标签分布 |
| 预警记录 | 15条 | 含未处理/已处理两种状态 |
| 首页统计 | 动态 | 基于情感记录实时计算 |

### 模拟交互效果

| 交互 | 模拟方式 |
|------|---------|
| 情感分析 | setTimeout 2~5秒延迟，随机返回情感结果 |
| 预警触发 | 分析结果为"焦虑/愤怒"时自动弹出预警弹窗 |
| 登录验证 | 固定账号密码，Mock.js 拦截登录请求 |
| 文件上传 | 前端模拟上传进度条，不实际上传 |
| 推送通知 | 站内通知通过 Pinia store 模拟实时推送 |

## 复杂度跟踪

| 复杂度项 | 为什么需要 | 拒绝更简单替代方案的原因 |
|---------|-----------|----------------------|
| ECharts 5 | 折线图/饼图/热力图/仪表盘是核心展示需求 | 原生 Canvas 开发成本过高 |
| Mock.js | 模拟真实数据结构和 API 响应格式 | 硬编码数据无法模拟动态交互 |
| Pinia | 跨页面状态共享（通知、用户信息、预警状态） | 组件间 props 传递无法满足全局状态需求 |
| Vue Router 权限守卫 | 三级角色页面访问控制（章程原则II） | 无守卫则无法演示权限拦截效果 |
